### 本轮修掉的三个缺陷（都是"跑起来"才发现的）
1. **静态库资源被链接器丢弃**。AUTORCC 生成的 `qrc_qt-md3.cpp` 在 `libqt-md3.a` 里
   没人引用其初始化器 → 整个 .obj 被丢掉 → 所有 `:/qt-md3/...` 查找失败
   （码点表、49 个经典 SVG、字体目录全废），且**影响任何链接静态库的应用**，不只测试。
   修法：新增 `MdResources::ensure()`，在库内 `Q_INIT_RESOURCE(qt_md3)` 制造未定义引用
   把资源对象拉进链接；`MdIcon` / `MdFont` 的取值入口各自调用。
2. **`MdRippleController::currentFrame()` 空闲时返回"可见"帧**。调用方若按
   `frame.valid` 而不是 `isActive()` 绘制，就会在首次按压前于左上角画出幽灵色块。
   现在空闲返回 invalid 帧；`MdRipple::geometryFor()` 也改为拒绝非正尺寸
   （原先把负数宽 clamp 成 0，等于掩盖调用方错误）。
3. **示例把 UTF-8 em dash 按 Latin-1 解码**，界面显示乱码。源码本身是正确的
   （`e2 80 94`），编辑器里看不出问题，只有截图能发现。

### 新增门禁 `TestMd3SourceEncoding`
两条规则：① 每个源文件必须是合法 UTF-8；② 禁止 `QString::fromLatin1(` /
`fromLocal8Bit(`（`QLatin1String(` 仅在该行纯 ASCII 时允许，`QLatin1Char` 放行）。

踩过的三个坑，别再犯：
- **按行检查抓不到这个 bug**：字面量在表格第 118 行，`fromLatin1` 调用在第 144 行。
  所以门禁是"禁用 API"而不是"检测误用"。
- **`file(STRINGS)` 会吞掉非法字节**（0x97 被当成行分隔符丢掉），所以 UTF-8 校验
  必须走 `file(READ)` 的原始字节。
- **CMake 正则不能喂大输入**：把 70 KB 的 hex 交给"分支+重复"型正则会让 CMake 直接
  崩掉（35 KB 的 `MdColorMath.cpp` 让进程退出 127）。正确做法：先用锚定的
  `^([0-7][0-9a-fA-F])*$` 快速判定纯 ASCII；非 ASCII 文件再用
  `MATCHALL ".."` 取对齐字节表，只把 ≥0x80 的字节送进状态机。
  注意 `[0-6]` 只覆盖到 0x6F，ASCII 要到 0x7F，必须写 `[0-7]`。
  这样 55 个文件 2 秒跑完；之前逐字节 `list(GET)`+`math(EXPR)` 要 154 秒。

## Windows 运行时部署（`cmake/QtMd3Deploy.cmake`）

`build/examples/qt-md3-example.exe` 是动态链接 Qt 的，依赖不在 build 树里，
所以双击报 "Qt6Core.dll was not found"，只有 Qt bin 在 PATH 上时才起得来。

**三个"标准答案"在本机全部不可用**，都是同一根因 —— 需要起子进程读命名管道，
而本机命名管道实例已耗尽（`QProcess: CreateFile failed.` 所有管道实例都在使用中）：
- `windeployqt`：`Unable to query qtpaths`；换 cmd、换 PowerShell、沙箱内外都一样。
  （Qt Creator 的 kit 环境里通常正常，属于本机环境问题。）
- `file(GET_RUNTIME_DEPENDENCIES)`：**直接挂死**，用 `notepad.exe` 当输入也一样，
  说明与我们的二进制无关。所以这个机制在本机既不能用也无法验证。
- `cmake -E env`：反而可用（只是简单 exec，不建管道），用它做门禁。

最终方案：在**配置阶段遍历链接图**推导 Qt 模块（`LINK_LIBRARIES` +
`INTERFACE_LINK_LIBRARIES`，正则从 `$<LINK_ONLY:Qt6::Gui>` 这类 genex 里取模块名，
再用 `TYPE == SHARED_LIBRARY` 过滤掉 `Qt6::XPrivate` 这类 interface 目标），
配上 GCC 运行时（编译器同级目录 glob）和 `platforms/` + `styles/` 插件整目录复制，
再写一个 `Prefix = .` 的 `qt.conf` 让 `plugins/` 从 exe 自己目录解析（可搬迁）。

**教训**：第一版手写了"gallery 链接的四个模块"这张表 → 每个测试二进制都起不来，
因为 `TestMd3Version` 还链接 `Qt6::Test`。**手写依赖表会腐烂，必须从链接图推导。**
症状是运行时 exit 127 / `0xc00000be`，编译器看不见。

**验证方法（重要）**：把 PATH 削到只剩 `C:\Windows\System32;C:\Windows` 再跑二进制，
这才是双击的真实环境。删除本地 `platforms/` 后必须失败（exit 127），
才能证明插件不是从 `C:\Qt` 加载的 —— 否则"改成可运行"是假象。

**新门禁**：`TestMd3DeploymentTestBinary` / `TestMd3DeploymentExample`，用
`cmake -E env --unset=QT_PLUGIN_PATH --unset=QT_QPA_PLATFORM "PATH=..."` 复现双击环境。
已负向验证：移走 `Qt6Test.dll` → 门禁失败，恢复 → 通过。CTest 现为 11 条。
